# 共同视觉合同

本文件只拥有跨法术的审美和表现约束。单术方案归[视觉卡](INDEX.md)，共同咏唱归[CASTING](CASTING.md)，代码及现有调参归[视觉实现说明](../../impl/visual/README.md)。当前是否占位、是否完成重做只在STATUS记录。

## 设计方向

原作动画/图片是第一依据，Minecraft像素3D是转译方式，PixelFX只辅助分层与烘焙。不同魔法必须有可辨认的轮廓、材质与运动节奏，不能只换颜色。高阶增加结构、阶段与余波，不等于无上限堆粒子。

水有流层、断续高光与破裂水滴；火有破边收尖火舌、小亮核与余烬，不用封闭白柱；冰土有棱面与生长/碎裂层次；风依靠流向、风带与卷吸表现。具体比例与造型必须在单术视觉卡定义，不能把这些共性当最终方案。

## 阶段与玩法边界

按玩法选择凝聚、释放、运动/维持、命中、解除/消散阶段；非弹体不强加飞行。表现消费服务端事件和状态，不反向决定伤害、MP、命中体积或持续时间。预警时间与可见性如果影响躲避或命中，仍由玩法卡拥有，视觉卡只定义如何显示。

保留空间方向一致性、可辨认作用范围与反馈。取消不播放成功命中；束缚解除不残留成功状态；第一人称近眼和持物不被大面积遮挡；原版物品动作优先。

## 材质、粒子与降级

清晰像素色块与受控透明分层，随机三维分布混合流向，不只堆在直线或单圆周；部件避免全同相抖动，循环平滑进入/退出。近景优先可读性，远景和密集场景降级。视觉等级读取已定义等级，不用耗魔猜等级。

新的粒数、面数、帧数和LOD阈值必须经设计/测量确定。旧实现中的512/192粒等调参不是永久设计约束；如改变性能上限需在任务卡给出预算与验证方式，不能直接取消预算。最终方案不承诺渲染器尚未提供的Bloom、屏幕折射或独立发光缓冲。

## 资产与验收

参考来源和授权规则见[REFERENCES](REFERENCES.md)。可编辑模型源与项目内导出都需保留；运行时不得依赖本机素材目录。是否使用Blockbench由具体形态与运行时评估，不为所有术强制独立模型或关键帧动画。

轮廓/方向/阶段/透明排序/近眼遮挡/多人同步/密集施法性能分别验收。离线预览和Blockbench截图只是制作证据，不代替游戏内验收；执行记录不写本合同。
