# 标准开发流程

任何功能按同一路径：intent（为什么）→ spec（必须发生什么）→ impl（怎么实现）→ 验收证据。文件模板与具体设计实例分离；模板更新不覆写现有数值。Markdown设计卡不是运行时配置，本次不把Java参数改成数据驱动。

## 修改范围先判断

| 变更 | 应改的设计 | 不需要改 |
|---|---|---|
| 水弹伤害/命中 | 水弹卡 | 魔法书设计 |
| 塞妮丝书收录/学习小游戏 | 学习合同/课程关系 | 各术伤害卡 |
| 所有咏唱时长 | 施法合同 | 102张卡重复时间表 |
| 只重命名类/移动包 | impl索引/代码 | 玩家意图和游戏数值 |
| 一次开发完成/测试重跑 | STATUS与日志 | 所有设计文档 |

## 一次任务的固定步骤

1. **界定意图**：用户希望改变什么体验、为什么；无关功能不改。未确认设计标提案。
2. **锁定规格**：复制[变更卡模板](templates/CHANGE.md)到`development/ACTIVE_TASK.md`，引用相关合同和法术ID，写精确差值、N/A、例外、至少正常/失败/边界Given/When/Then。新术复制[法术设计模板](templates/SPELL.md)到`spec/magic/spells/<id>.md`，不能把模板当具体设计。
3. **用户决策**：只有缺少影响玩法的必要决定才询问；用户已授权范围内继续实现。禁止以现有bug反向改spec。未解决差异登记reference/SPEC_DEVIATIONS。
4. **实现映射**：在变更卡写纯规则、用例、世界端口、装配、表现、存档与测试位置；仅在真实变化点用经典模式，遵守SOLID。
5. **实现和验证**：纯函数测边界，模块测真实用例/失败事务，资源和架构跑构建；世界、视觉、联机、性能分别验收。不得用字符串引用数量冒充覆盖率。
6. **交付**：运行`.\gradlew.bat build --offline`；记录真实命令/退出码/证据。游戏启动和Git暂存/提交需要用户明确要求，本次不继承之前的git add授权。
7. **收尾**：仅更新发生变化的intent/spec/impl；只在STATUS更新当前结果/下一步；日志追加一次开发经过。完成的ACTIVE_TASK移入`logs/tasks/`，STATUS不再指它继续执行。不在设计卡追加“本次完成了”。

## AI最小阅读与上下文恢复

根AGENTS→docs/README→STATUS；存在活动任务再读ACTIVE_TASK。然后只读任务引用的intent、系统合同、单术卡、相关impl和代码。不得全量读取102卡或archive。压缩前把目标、决定、改动文件、命令结果与下一步写入ACTIVE_TASK；恢复先核对它与git diff，不凭摘要猜完成。

## 完成标准

规格无未决必要字段；代码/资源接通；相关自动检查通过；未执行的实机项目明确NOT_RUN；索引可定位；无进度复制和多重有效规则。涉及实际视觉但未启动游戏，只能交付实现，不能宣称视觉验收通过。
