# 视觉重做流程

1. 读视觉意图、共同合同、对应视觉卡与玩法卡；查看实际参考，不以当前游戏动画作为最终方案。
2. 复制[视觉模板](templates/VISUAL.md)，在对应卡补实参考证据、轮廓、分镜和适配取舍；保留明确要求，尚未设计的字段写未定，不自动批准占位外形。
3. 在活动变更卡记录范围、方案决定、实现路径与验收标准。修改玩法预警/体积/时间需同时走玩法变更；仅换表现不改玩法数值。
4. 按需要选择程序网格、模型或两者结合；评估再决定是否Blockbench建模。准备色板、像素材质、动画曲线、分层粒子、音效和LOD，不盲目叠粒子。
5. 单术先完成参考对照预览，检查正侧后、上下瞄准与近眼遮挡，再接真实事件。共享咏唱变更另外回归弹体/持续/领域/注魔。
6. 文档检查与离线构建后，只有用户允许才运行游戏验收。预览、实现和实机通过分开记；未实测视觉不得标为最终验收。
7. 稳定后更新impl定位和资源引用；经检查无引用再清理旧资产。结果只写STATUS，制作过程写logs；不在102卡追加日志。

只改视觉的最小阅读集合：intent/VISUAL → visual/CONTRACT → visual/CASTING（涉及共享层时）→ visual/spells/<id> → magic/spells/<id>只读约束 → impl与相关代码。
