# 魔法系统统一开发模板（Minecraft 26.1 / Fabric / Java 25）

## 本版使用方法

1. 创造模式「工具与实用物品」取得「塞妮丝的魔法书」，或执行：

   ```text
   /give @s mushokutenseiorigin:zenith_greyrat_magic_book
   ```

2. 手持魔法书右键，点击「学习水弹咏唱」。学习是永久解锁，不要求每次吟唱。首次学习自动加入轮盘并选中；最多装入 10 个，槽满仍可学习。
3. **G**：魔法知识。查看已学魔法、轮盘列表、魔力消耗、冷却、属性和伤害。移除只卸载，不遗忘。
4. **按住 R**：打开黑色 50% 透明背景的轮盘，鼠标移到法术槽，松开确认。空白处松开保留原选择；Esc 取消。没有已加载法术时显示空状态。
5. **按住 V**：连发，松开停止。空手、手持普通物品均可，不依赖法杖。按键均可在原版控制设置的「无职转生：魔法」中重绑。
6. HUD 蓝色条和数字位于九格栏右侧、底边齐平，标准宽度与一行原版血量相同（81 GUI 像素）；已选法术名称使用原版药水背景显示在右上角；无已学法术时不显示法术名称。普通玩家 GUI 无上限修改入口。

任何 GUI、失焦、死亡、旁观、吃东西/拉弓等物品使用都会阻止施法；结束后必须松开并重新按 V。原版物品使用动作优先，不取消原版行为；已经发射的弹体继续存在。

## 规则与动作分镜

| 阶段 | 服务端行为 | 客户端表现 |
|---|---|---|
| 解锁 | 检查玩家实际持有魔法书，学习 water_ball | 按钮显示已学会，自动装入可用槽 |
| 按 V | 收到 arm 与 cast 请求，校验存活、非旁观、没有使用物品、已学/已装/已选、魔力、冷却 | 不提前假扣魔力或播放成功动作 |
| 成功释放，第 0 tick | 单次扣 1 魔力、生成弹体；失败生成则回滚；设置 2 tick 冷却及姿态 | 物理右手向前抬到胸口附近，HUD 由服务端状态更新 |
| 第 1 tick | 冷却剩余 1 tick | 继续抬手；身体仍可移动 |
| 第 2 tick | 冷却结束；再次成功施法刷新动作时间 | 连发时保持抬手；否则恢复原版姿态 |
| 原版使用物品 | 拒绝施法，不扣魔力、不生成新弹体；清除施法姿态 | 立即服从吃东西、拉弓等原版动作 |
| 命中/超时 | 实体或方块命中后消失；实体 1 点伤害；100 tick 寿命；不强制加载区块 | 0.25 方块水立方体、原版动画水纹理、少量水花 |

水弹使用雪球式初速度 1.5、原版 ThrowableProjectile 的重力和阻力；不放水、不破坏方块。保留原版护甲、PVP 和受伤无敌时间，因此每秒 10 发不代表同一目标每秒受到 10 次伤害。魔力不足提示节流至最多每秒一次。没有添加额外法阵、蓄力等待或音效。

左右手偏好不改变施法手：固定物理右手。第三人称基于 HumanoidModel，普通/纤细皮肤共用动作；第一人称只调整对应右手渲染路径。最终动作角度、持物遮挡和贴合需要进游戏验收。

## 配置、管理与持久化

首次运行自动创建游戏/服务端目录下的 `config/mushokutenseiorigin-magic.json`：

```json
{
	"maximumMana": 100
}
```

这是**首次创建玩家魔法数据时的默认上限**，范围 1–1000000。修改文件后重启生效；已有玩家的上限以其存档为准，防止覆盖管理接口或后续成长系统的调整。

管理员（原版 GAMEMASTERS，通常权限等级 2）可执行：

```text
/mtmagic maxmana @s 150
/mtmagic maxmana @a 100
```

增加上限不回满；降低上限截断当前魔力。代码接口：`MagicSystem.setMaximum(ServerPlayer, int)`，必须在服务端线程调用。没有赋予普通玩家修改上限的网络操作。

魔力、最大值、在线计时、冷却、已学列表、轮盘顺序和当前选择通过 Fabric Attachment Codec 保存在玩家数据。重进不会回满，计时离线不增长；数据跟随存档，备份整个世界即可。修改法术 ID 前需要设计数据迁移，当前会过滤已不存在的法术 ID。

- 在线且存活累计 **24000 服务端 tick** 回满，随后重新计时；低 TPS 下实际时间相应变长。
- 成功睡眠推进到早晨时，仅该次实际睡眠的玩家回满；手动起床、未推进时间不恢复。
- 死亡重生回满魔力、重新计时；保留知识、轮盘、选择和上限。
- 弹体保存已存活 tick；重载不重置寿命。前方区块未加载时移除，不增加区块票据。

## 文件职责：后续法术沿用此分层

| 文件 | 职责 |
|---|---|
| `magic/SpellDefinition.java` | 法术 ID、魔力、伤害、冷却、寿命、属性的单一数值入口 |
| `magic/MagicState.java` | 不可变玩家状态、学习/装槽/选择/扣除/恢复、Codec |
| `magic/MagicAttachments.java` | 持久化状态与仅显示用的抬手同步 |
| `magic/MagicSystem.java` | 唯一服务端校验/扣魔力/生成入口，连接/死亡/tick 生命周期 |
| `magic/MagicConfig.java`、`MagicCommands.java` | 默认配置和管理员上限接口 |
| `magic/MagicActionPayload.java` | 有长度上限的动作请求、连接内递增序列；不接受客户端传入伤害或魔力数值 |
| `magic/WaterBallEntity.java` | 本法术命中、伤害、寿命、存档和水花 |
| `magic/MagicSounds.java` | CHARGE、RELEASE、IMPACT 扩展接口，目前无声；瞬发无实际蓄力阶段 |
| `item/ZenithGreyratMagicBookItem.java`、`item/ModItems.java` | 书的属性与统一物品注册 |
| `client/magic/MagicClient.java` | 可重绑按键、客户端连发及打断状态 |
| `client/magic/MagicScreens.java` | 知识/学习面板、轮盘、HUD |
| `client/magic/WaterBallRenderer.java` | 立方体延迟渲染、原版图集水纹理 |
| `mixin/MagicSleepMixin.java` | 成功跳夜判定；只改恢复，不替换原版睡眠流程 |
| 客户端 `mixin/Magic*Pose/State/Humanoid/FirstPerson*` | 每实体提取姿态和两种视角动作 |
| `src/test/.../magic/MagicStateTest.java` | 不启动游戏的逻辑测试 |

通用 Java 放 `src/main`；客户端类只放 `src/client`。沿用包名 `com.example.examplemod` 和命名空间 `mushokutenseiorigin`。UTF-8、LF、Tab 缩进、同行大括号。物品必须复制 `docs/ADDING_ITEMS.md` 模板，不新增平行物品注册器。

### 新法术实施顺序

1. 在 `SpellDefinition` 添加唯一 ID 与定义，并加入 `ALL`。冷却统一使用整数 tick；不要仅靠客户端计时。
2. 添加法术实体/效果执行器与注册。**当前 MagicSystem 的 cast 分支只生成水弹**；新增法术必须在该分支按已校验的定义 ID 分派到对应执行器，禁止只加入 ALL 就交付。将伤害、寿命等数值从对应定义读取，不复制水弹常量。
3. 扩展学习来源的服务端白名单。当前魔法书只对应水弹；新增其他书必须校验书与法术的对应关系，不接受任意 learn 请求。
4. 继续复用 `MagicState.canCast/cast` 和统一原子扣除流程。失败不得消耗；不能绕过冷却、上次扣除、原版物品使用和序列校验。不能由客户端生成有伤害的实体。
5. 添加客户端渲染并注册；新增音效通过现有阶段接口分派。GUI 当前水属性/伤害详情和学习按钮是首个法术专用，新增效果时改成由定义驱动的描述，不复制页面。
6. 添加中英文语言键、图标和必要的物品资源；编辑源保存在 `D:\LibreSprite-art-source\<功能名>\`，游戏使用资源必须复制进项目，运行时不得引用本机绝对路径。3D 物品遵守已有模型源与导出规范。
7. 增加有意义的状态/命中测试，运行构建，再按下表做游戏验收。不要自动 commit。

## 26.1 图集接口注意事项

`EntityRendererProvider.Context.getAtlas()` 接收逻辑图集 ID，例如 `AtlasIds.BLOCKS`（`minecraft:blocks`），不接收纹理文件路径。
`RenderTypes.entityTranslucent()` 的纹理参数则使用 `TextureAtlas.LOCATION_BLOCKS`（`minecraft:textures/atlas/blocks.png`）。
二者类型同为 Identifier，混用能编译但会在启动资源重载时产生 `Invalid atlas id`，继而报水弹渲染器创建失败并黑屏。
本次已修正查询参数；构建验证不等同于客户端启动验证。

## MVP 第二轮调整

- 魔法书右键使用原版 BookViewScreen 的书页、页码、背景和完成按钮，额外增加学习咏唱按钮；不提供编辑/签名功能。G 知识管理页面不变。
- 当前法术名称使用原版 `hud/effect_background` 精灵、24 像素行高，右上角对齐；有真实药水效果时移至其下方避免重叠，无选择则隐藏。
- 魔力槽标准宽 81 GUI 像素，放在九格栏右侧 6 像素处，底边齐平，数字在槽上方。GUI 空间不足时整体缩小，防止出屏。
- 作弊权限命令（与 maxmana 相同权限）：

```text
/mtmagic restore @s 30
/mtmagic restore @s full
/mtmagic restore @a full
```

参数恢复量为正整数，恢复后最多为该玩家上限；full 直接回满。恢复仅改当前魔力，不改变上限、冷却、在线恢复计时或知识。反馈显示实际恢复总量，支持原版玩家选择器；没有作弊权限无法执行。

测试：分别在缺魔/满魔时恢复指定值和 full，检查上限截断、权限与多人选择器；检查不同 GUI 缩放、右上角药水共存、空法术隐藏、魔法书书页与学习按钮及重复学习。
