## 当前操作


1. 创造模式「无职转生」取得「塞妮丝的魔法书」，或执行：

   ```text
   /give @s mushokutenseiorigin:zenith_greyrat_magic_book
   ```

2. 手持塞妮丝的魔法书右键，翻过导论，在全部102个已注册法术/能力页分别点击学习按钮即可直接学会，无需前置或学习咏唱小游戏。学习是永久解锁，不要求每次吟唱。首次学习自动加入轮盘并选中；最多装入 10 个，槽满仍可学习。
3. **G**：魔法知识。查看已学魔法、轮盘列表、魔力消耗、冷却、属性和伤害。移除只卸载，不遗忘。
4. **按住 R**：在视角中央打开小圆盘，左右键点击扇区选择，松开 R 关闭。可继续移动、跳跃、潜行；鼠标不与世界交互，其他 GUI 中不能打开。
5. **按住 V**：连发，松开停止。空手、手持普通物品均可，不依赖法杖。按键均可在原版控制设置的「无职转生：魔法」中重绑。
6. HUD 蓝色条和数字位于九格栏右侧、底边齐平，标准宽度与一行原版血量相同（81 GUI 像素）；已选法术名称使用原版药水背景显示在右上角；无已学法术时不显示法术名称。普通玩家 GUI 无上限修改入口。

任何 GUI、失焦、死亡、旁观、吃东西/拉弓等物品使用都会阻止施法；结束后必须松开并重新按 V。原版物品使用动作优先，不取消原版行为；已经发射的弹体继续存在。


## 服务端边界与实现职责

- `SpellDefinition.ALL`是已注册法术目录与定义入口；新增定义必须接通服务端执行、教材、客户端表现和资源，不能仅注册即交付。
- `MagicActionReceiver`、输入会话与各施法用例检查玩家、知识、装槽、选择、输入心跳、物品使用、MP与冷却；`MagicSystem`保留公开状态接口和兼容实体别名；客户端不决定伤害、费用或成功释放。网络动作限制长度并校验序列，服务端核查实际持书与课程。
- `PreparationRuntimeAdapter`处理准备阶段，`SpellExecutors`连接现有执行器；持续、注魔、组合、阵面及核心按各自规格处理，不套用早期水弹瞬发模板。成功释放才付主术费用；失败回滚，取消准备不得免费生成效果。
- `MagicState`负责玩家状态，Attachment/Codec保存，客户端同步仅用于显示。`MagicBooks`及课程逻辑必须区分塞妮丝102项直学、入门39项直学、分类教材前置及学习谱。
- `src/main`仅通用/服务端代码，`src/client`仅客户端代码；不得在通用代码导入客户端类。保留注册ID、存档键与资源命名空间。
- 原版使用物品优先；GUI、失焦、死亡、旁观等打断后必须松开再按V。轮盘只透传移动类按键，不透传攻击/使用；关闭后先松鼠标，防止误操作。
- 碰撞、权限、PVP、无敌帧、护盾、地形续期和永久地形特例以正式逐术规格为准；视觉曲面不得擅自扩大命中体。

## 配置、管理与持久化


首次运行自动创建游戏/服务端目录下的 `config/mushokutenseiorigin-magic.json`：

```json
{
	"maximumMana": 100
}
```

这是**首次创建玩家魔法数据时的默认上限**，范围 1–1000000。修改文件后重启生效；已有玩家的上限以其存档为准，防止覆盖管理接口或后续成长系统的调整。

管理员（原版 GAMEMASTERS，通常权限等级 2）可执行：

```text
/mtmagic maxmana @s 150
/mtmagic maxmana @a 100
```

增加上限不回满；降低上限截断当前魔力。代码接口：`MagicSystem.setMaximum(ServerPlayer, int)`，必须在服务端线程调用。没有赋予普通玩家修改上限的网络操作。

魔力、最大值、在线计时、冷却、已学列表、轮盘顺序和当前选择通过 Fabric Attachment Codec 保存在玩家数据。重进不会回满，计时离线不增长；数据跟随存档，备份整个世界即可。修改法术 ID 前需要设计数据迁移，当前会过滤已不存在的法术 ID。

- 在线且存活累计 **24000 服务端 tick** 回满，随后重新计时；低 TPS 下实际时间相应变长。
- 成功睡眠推进到早晨时，仅该次实际睡眠的玩家回满；手动起床、未推进时间不恢复。
- 死亡重生回满魔力、重新计时；保留知识、轮盘、选择和上限。
- 有飞行时限的弹体保存计时，重载不重置；基础弹体不设时间/距离上限。前方区块未加载时按逐术规则暂停或移除，不增加区块票据。


管理员还可执行 `/mtmagic restore @s 30`、`/mtmagic restore @s full`（支持玩家选择器）。只改当前MP，不改上限、冷却、恢复计时或知识。新增配置、阵面、核心、传送、通信和召唤命令详见扩展规范的当前操作说明，不自动提高玩家MP供测试。

## 每次开发流程

1. 阅读文档入口和涉及的逐术规格，记录用户intent、确认spec与当前实现的差异；冲突不能凭旧注释或现有bug擅自裁决。
2. 保留已有工作区改动；按当前结构实现最小范围变更。架构v2已获准；先读唯一重构状态与最终追踪表，已完成切片不重复实施。
3. 数值从定义或明确的专项规则读取；复用统一校验、失败回滚、状态同步及权限边界，新增执行器不能绕过它们。
4. 接通课程、图标、中英文文案、模型/纹理/粒子及渲染注册。物品遵守[统一物品模板](ADDING_ITEMS.md)，模型源随项目保留；运行时不能依赖本机绝对路径。
5. 为实际规则增加有意义的纯逻辑测试；编译/资源检查与真实游戏集成检查分别记证据，不用离线网格图冒充游戏画面。
6. Java采用UTF-8、LF、Tab、同行大括号；工具生成网格不手改顶点。运行 `.\gradlew.bat build --offline`（包含verifyMagic）；有意改变测试范围时解释原因。
7. 同步相关正式设定、教材与视觉规范及文档入口的进度。不得再增加phase批次文档作为新真相来源。
8. 未经用户本次明确要求不启动Minecraft、不执行git add/commit/push。当前用户暂停实机验收，不能因此标记验收完成。

## 26.1 图集接口注意事项


`EntityRendererProvider.Context.getAtlas()` 接收逻辑图集 ID，例如 `AtlasIds.BLOCKS`（`minecraft:blocks`），不接收纹理文件路径。
`RenderTypes.entityTranslucent()` 的纹理参数则使用 `TextureAtlas.LOCATION_BLOCKS`（`minecraft:textures/atlas/blocks.png`）。
二者类型同为 Identifier，混用能编译但会在启动资源重载时产生 `Invalid atlas id`，继而报水弹渲染器创建失败并黑屏。
本次已修正查询参数；构建验证不等同于客户端启动验证。


## 验收边界

离线构建不能证明客户端加载、透明排序、双视角手臂、多人同步、密集粒子帧率、地形保护或跨维回滚正确。真实游戏验收应覆盖：学习/重复学习与持书伪造、退出重进/死亡、输入打断与重绑、各术费用/冷却/命中、原版物品优先、普通及纤细皮肤、明暗背景、复杂地形/未加载区块、多人及独立服务端。每项分别标记未测/通过/失败并附证据，不写笼统“全部完成”。
