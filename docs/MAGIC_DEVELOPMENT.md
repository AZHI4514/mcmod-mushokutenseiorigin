# 魔法系统统一开发模板（Minecraft 26.1 / Fabric / Java 25）

## 本版使用方法

1. 创造模式「无职转生」取得「塞妮丝的魔法书」，或执行：

   ```text
   /give @s mushokutenseiorigin:zenith_greyrat_magic_book
   ```

2. 手持魔法书右键，翻过导论，在八个法术页分别点击学习按钮。学习是永久解锁，不要求每次吟唱。首次学习自动加入轮盘并选中；最多装入 10 个，槽满仍可学习。
3. **G**：魔法知识。查看已学魔法、轮盘列表、魔力消耗、冷却、属性和伤害。移除只卸载，不遗忘。
4. **按住 R**：在视角中央打开小圆盘，左右键点击扇区选择，松开 R 关闭。可继续移动、跳跃、潜行；鼠标不与世界交互，其他 GUI 中不能打开。
5. **按住 V**：连发，松开停止。空手、手持普通物品均可，不依赖法杖。按键均可在原版控制设置的「无职转生：魔法」中重绑。
6. HUD 蓝色条和数字位于九格栏右侧、底边齐平，标准宽度与一行原版血量相同（81 GUI 像素）；已选法术名称使用原版药水背景显示在右上角；无已学法术时不显示法术名称。普通玩家 GUI 无上限修改入口。

任何 GUI、失焦、死亡、旁观、吃东西/拉弓等物品使用都会阻止施法；结束后必须松开并重新按 V。原版物品使用动作优先，不取消原版行为；已经发射的弹体继续存在。

## 规则与动作分镜

| 阶段 | 服务端行为 | 客户端表现 |
|---|---|---|
| 解锁 | 检查玩家实际持有对应教材，学习该页的四元素法术之一 | 按钮显示已学会，自动装入可用槽 |
| 按 V | 收到 arm 与 cast 请求，校验存活、非旁观、没有使用物品、已学/已装/已选、魔力、冷却 | 不提前假扣魔力或播放成功动作 |
| 成功释放，第 0 tick | 按当前法术扣魔力并生成弹体，生成失败回滚；设置定义中的冷却，姿态维持 2 tick | 物理右手向前抬到胸口附近，HUD 由服务端状态更新 |
| 第 1 tick | 冷却剩余 1 tick | 继续抬手；身体仍可移动 |
| 第 2 tick | 冷却结束；再次成功施法刷新动作时间 | 连发时保持抬手；否则恢复原版姿态 |
| 原版使用物品 | 拒绝施法，不扣魔力、不生成新弹体；清除施法姿态 | 立即服从吃东西、拉弓等原版动作 |
| 命中/超时 | 实体或方块命中后消失；实体 1 点伤害；100 tick 寿命；不强制加载区块 | 0.25 方块水立方体、原版动画水纹理、少量水花 |

水弹使用雪球式初速度 1.5、原版 ThrowableProjectile 的重力和阻力；不放水、不破坏方块。保留原版护甲、PVP 和受伤无敌时间，因此每秒 10 发不代表同一目标每秒受到 10 次伤害。魔力不足提示节流至最多每秒一次。没有添加额外法阵、蓄力等待或音效。

左右手偏好不改变施法手：固定物理右手。第三人称基于 HumanoidModel，普通/纤细皮肤共用动作；第一人称只调整对应右手渲染路径。最终动作角度、持物遮挡和贴合需要进游戏验收。

## 配置、管理与持久化

首次运行自动创建游戏/服务端目录下的 `config/mushokutenseiorigin-magic.json`：

```json
{
	"maximumMana": 100
}
```

这是**首次创建玩家魔法数据时的默认上限**，范围 1–1000000。修改文件后重启生效；已有玩家的上限以其存档为准，防止覆盖管理接口或后续成长系统的调整。

管理员（原版 GAMEMASTERS，通常权限等级 2）可执行：

```text
/mtmagic maxmana @s 150
/mtmagic maxmana @a 100
```

增加上限不回满；降低上限截断当前魔力。代码接口：`MagicSystem.setMaximum(ServerPlayer, int)`，必须在服务端线程调用。没有赋予普通玩家修改上限的网络操作。

魔力、最大值、在线计时、冷却、已学列表、轮盘顺序和当前选择通过 Fabric Attachment Codec 保存在玩家数据。重进不会回满，计时离线不增长；数据跟随存档，备份整个世界即可。修改法术 ID 前需要设计数据迁移，当前会过滤已不存在的法术 ID。

- 在线且存活累计 **24000 服务端 tick** 回满，随后重新计时；低 TPS 下实际时间相应变长。
- 成功睡眠推进到早晨时，仅该次实际睡眠的玩家回满；手动起床、未推进时间不恢复。
- 死亡重生回满魔力、重新计时；保留知识、轮盘、选择和上限。
- 弹体保存已存活 tick；重载不重置寿命。前方区块未加载时移除，不增加区块票据。

| `client/magic/MagicScreens.java` | 知识/学习面板、轮盘、HUD |

### 新法术实施顺序

1. 在 `SpellDefinition` 添加唯一 ID 与定义，并加入 `ALL`。冷却统一使用整数 tick；不要仅靠客户端计时。
2. 添加法术实体/效果执行器与注册。**当前 MagicSystem 通过 SpellExecutors 分派六种单目标弹体、火断路径攻击或自身治疗**；新增法术必须在该分支按已校验的定义 ID 分派到对应执行器，禁止只加入 ALL 就交付。将伤害、寿命等数值从对应定义读取，不复制水弹常量。
3. 扩展学习来源的服务端白名单。当前两本教材都对应八个法术，并检查定义中的学习前置；新增其他书必须校验书与法术的对应关系，不接受任意 learn 请求。
4. 继续复用 `MagicState.canCast/cast` 和统一原子扣除流程。失败不得消耗；不能绕过冷却、上次扣除、原版物品使用和序列校验。不能由客户端生成有伤害的实体。
5. 添加客户端渲染并注册；新增音效通过现有阶段接口分派。GUI 的属性、数值和学习按钮由法术定义与教材目录驱动；新增特殊效果应提供对应文案，不复制页面。
6. 添加中英文语言键、图标和必要的物品资源；编辑源保存在 `D:\LibreSprite-art-source\<功能名>\`，游戏使用资源必须复制进项目，运行时不得引用本机绝对路径。3D 物品遵守已有模型源与导出规范。
7. 增加有意义的状态/命中测试，运行构建，再按下表做游戏验收。不要自动 commit。

## 26.1 图集接口注意事项

`EntityRendererProvider.Context.getAtlas()` 接收逻辑图集 ID，例如 `AtlasIds.BLOCKS`（`minecraft:blocks`），不接收纹理文件路径。
`RenderTypes.entityTranslucent()` 的纹理参数则使用 `TextureAtlas.LOCATION_BLOCKS`（`minecraft:textures/atlas/blocks.png`）。
二者类型同为 Identifier，混用能编译但会在启动资源重载时产生 `Invalid atlas id`，继而报水弹渲染器创建失败并黑屏。
本次已修正查询参数；构建验证不等同于客户端启动验证。

## MVP 第二轮调整

- 魔法书右键使用原版 BookViewScreen 的书页、页码、背景和完成按钮，额外增加学习咏唱按钮；不提供编辑/签名功能。G 知识管理页面不变。
- 当前法术名称使用原版 `hud/effect_background` 精灵、24 像素行高，右上角对齐；有真实药水效果时移至其下方避免重叠，无选择则隐藏。
- 魔力槽标准宽 81 GUI 像素，放在九格栏右侧 6 像素处，底边齐平，数字在槽上方。GUI 空间不足时整体缩小，防止出屏。
- 作弊权限命令（与 maxmana 相同权限）：

```text
/mtmagic restore @s 30
/mtmagic restore @s full
/mtmagic restore @a full
```

参数恢复量为正整数，恢复后最多为该玩家上限；full 直接回满。恢复仅改当前魔力，不改变上限、冷却、在线恢复计时或知识。反馈显示实际恢复总量，支持原版玩家选择器；没有作弊权限无法执行。

测试：分别在缺魔/满魔时恢复指定值和 full，检查上限截断、权限与多人选择器；检查不同 GUI 缩放、右上角药水共存、空法术隐藏、魔法书书页与学习按钮及重复学习。


## 四元素基础攻击批次

| 法术 ID | 名称 | 魔力 | 伤害（生命值） | 冷却 tick | 重力 | 附加效果 |
|---|---|---:|---:|---:|---:|---|
| water_ball | 水弹 | 1 | 1 | 2 | 0.03 | 水花 |
| fireball | 火球弹 | 3 | 3 | 12 | 0.03 | 火焰直接伤害，不点燃 |
| wind_ball | 风弹 | 2 | 1 | 8 | 0.01 | 成功伤害后水平推退，强度 0.6 |
| rock_bullet | 石弹 | 3 | 4 | 12 | 0.06 | 下坠较明显 |

四种弹体大小 0.25 格、初速 1.5 格/tick、寿命 100 tick，使用原版投掷物阻力与碰撞。数值统一在 SpellDefinition 修改。
冷却是玩家全局冷却，切换法术不能绕过；客户端维持每 2 tick 请求一次，服务端按各法术冷却决定成功释放。
每次成功施法的物理右手姿态固定 2 tick，不随新法术较长冷却延长。吃东西等原版使用动作仍优先。

火球使用自定义 basic_fireball 伤害类型，并加入原版 is_fire、is_projectile 标签，遵守抗火、护甲、PVP 和受伤无敌帧。
伤害 JSON 中 effects=burning 仅指定受伤反馈类别，不给目标添加燃烧时间；不会放火或爆炸，也不破坏方块。
风弹追加击退只在成功造成伤害后执行，并受原版击退抗性影响。无敌帧免伤时不追加击退。

两本教材：zenith_greyrat_magic_book（塞妮丝的魔法书）、basic_attack_magic_primer（初级攻击魔法入门）。
两书共用 MagicBooks 课程目录、导论和四种法术学习页，区别仅名称与图标。创造工具分页可取得，也可 /give。
导论涵盖魔术、元素、七级、发动方式、练习与守则。正式咏唱、成长、状态、混合术仅为背景介绍，本批未启用。
原版 BookViewScreen 提供书页、页码、翻页、完成；只有法术页显示对应学习按钮。已学课程不重复占槽。
32×32 RGBA 图标逐像素绘制，编辑源归档在 D:\LibreSprite-art-source\magic\basic-projectiles\。

### 后续依赖接入口

- SpellDefinition.castMode 预留瞬发、咏唱、蓄力、持续；当前只有 INSTANT 可施放，不把未实现方式当瞬发放行。
- SpellDefinition.requirements 与 SpellHooks.requirement 提供服务端前置检查。未知依赖默认拒绝，基础四术没有外部依赖。
- SpellHooks.afterHit 是服务端成功伤害后的挂点，未来状态系统可接入；当前不添加疾病、湿身或燃烧。
- SpellHooks.CastSource 预留 WAND；当前只允许 KEYBOARD，法杖需下一批接入并验证真实持物。
- 增加伤害类型时补全数据标签与死亡文案；添加新实体须注册客户端渲染器。不要修改旧 water_ball ID，已有存档保持有效。

### 本批手动验收

1. 两本书各翻 10 页，确认相同导论/四术、按钮对应当前页，重复学习不重复；中文和英文、窗口缩放都检查。
2. G/R 检查四术属性、伤害、魔力和选择；分别按住 V 核对耗魔与冷却，切换不可绕过冷却。
3. 火球打普通目标与抗火目标，确认前者受伤、后者免疫；不点燃实体/地形，不爆炸。
4. 风弹成功伤害后推退，护甲/无敌帧/PVP 规则正常；石弹比水弹更明显下坠。
5. 四术命中即消失、5 秒上限、重进保留知识魔力；两玩家互看弹体与施法动作。

未自动启动客户端。build/verifyMagic 只验证编译、资源打包和离线状态逻辑，不能替代以上游戏内验收。

## 小型点击轮盘

按住 R 打开，左右键点击扇区选择，松开 R 关闭；Esc 关闭。空白处点击不改选。圆盘位于窗口中心，面积约窗口 1/9（超宽窗口限制在短边内），仅圆盘有半透明底色，无全屏遮罩或模糊。打开时仍停止施法，关闭后须重新按 V。物品仅在无职转生分类展示，示例物品从创造分类隐藏但保留注册以兼容旧存档。

## 按住轮盘与移动隔离

按住绑定的 R 显示，松开立即关闭，不在松开时自动改选；左右键点击扇区只选择法术且保持打开。只透传前后左右、跳跃、潜行及疾跑的物理绑定，不透传攻击/使用。关闭后鼠标须先松开，防止按住造成误攻击/使用。其他界面（含物品栏）中不响应 R；若一直按住 R 退出其他界面，须先松开再按才能打开。无焦点时关闭轮盘并停止透传。验收需覆盖移动中开关轮盘、按住鼠标松 R、物品栏中按 R 以及按键重绑。


## 第二批：基础攻击扩展与初级治愈

两本教材都为6页导论+8页法术，共14页。水矢、冰击需先学水弹；火断需先学火球弹；治愈无知识前置。
学习条件由 SpellDefinition.learningRequirements 声明、MagicState.learn 强制校验，重复请求或伪造学习请求不可绕过。
前置未满足时禁用学习按钮，书页仍自由翻阅；已学法术、轮盘及已有存档 ID 保持有效。

SpellDefinition.Execution 区分 PROJECTILE、FLAME_SLICE、SELF_HEAL；SpellExecutors 只在服务端执行。
服务端先检查通用施法条件与治疗缺血条件，再扣魔力/进入全局冷却；实体生成或治疗失败则恢复原状态。
Healing 调用原版 heal，仅自己、活着且缺血时有效；最多回复4点、截断到生命上限，不加吸收生命、不解除疾病/状态、不复活。
差1点生命仍按成功施法消耗8魔力，回复1点；满血则不扣魔力、不进入冷却、不播放成功动作。

火断命中体为随准星朝向旋转的3格宽×1格高×1格厚长方体，沿释放瞬间方向直线飞行，最远10格。
FlameSliceVolume使用连续分离轴扫掠检测生物包围盒，含侧边、初始重叠、上下瞄准，不使用中心射线或碰撞点到目标的视线过滤。
首次扫到活着的非旁观生物（排除施术者）时，移动至刚进入相交的位置，以首个命中生物为中心，对水平3×3格、其身体高度范围内的全部生物各结算一次4点火伤，然后消失。
未进入该命中区域的更远目标不会被伤害。PVP关闭、抗火、护甲和受伤无敌帧仍生效，不点燃、不爆炸。
方块只在完整封住3×1截面时阻挡。先用碰撞形状的各AABB与截面相交，逐个从截面多边形扣除覆盖，剩余面积非零即允许穿过。
截面覆盖为几何裁剪，不用少量采样点把小孔误判为堵死；沿飞行方向每1/32格检查体积范围内的截面，原版极薄碰撞或其他模组特殊碰撞需实测。
部分方块遮挡时长方体保持完整，不削减伤害或形状，也不删除方块。完整封堵早于/等于生物接触时优先停止。
FlameSliceFlight保存已走距离，存活tick继续保存；查询前验证全部扫掠区域区块已加载，未加载则移除，不强制加载。

显示沿用现有动作、GUI和HUD。水矢是细长水纹理，冰击是冰纹理块，火断是原版动画火焰薄刃；治疗只添加少量原版绿色粒子。
知识页对治愈显示恢复值而非伤害值；新法术沿用现有轮盘，上限仍10。本批未增物品或第三方依赖，没有新的绘图素材文件。
SpellHooks.afterHit 接受 Projectile，六种单目标弹体与火断共用后续状态挂点；治疗对象后续可在执行器层扩展。

### 本批游戏内验收

1. 两本书各14页：可自由翻页；未学水弹/火球时对应扩展术不能学，学习基础术后按钮解锁；重复学习不占槽。
2. G分两页查看8术、轮盘8槽，选择和卸载正常，治疗显示恢复值；按住R移动跳跃潜行不受影响。
3. 水矢比水弹更快更细、下坠小；冰击较慢、下坠明显且不冻结/放置冰块；命中消失和寿命正确。
4. 火断侧边擦过生物可命中，同一3×1×1火断体内多个目标各受伤一次后消失；远处未进入体积的生物不受伤。
5. 火断射程10格：可穿单块、半砖、带孔墙；完整墙/天花板截面阻挡。抗火免疫、PVP关闭不伤玩家、不点燃/爆炸、不强载。
6. 治疗满血不扣魔力/冷却，缺血最多恢复4；不足1颗心时不超上限；低魔力/冷却期间不治疗，死亡不能复活。
7. 连发及切换不能绕过全局冷却；原版吃东西/拉弓优先；已学8术、耗魔、选择重进保留。

### 火断准星与透明边缘修正
